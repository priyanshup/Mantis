# Success metrics

1. Start from the outcome (pm-feature-framing). Pick the HEART category that fits: Happiness, Engagement, Adoption, Retention, Task success.
2. Go from Goal to Signal (the behaviour that shows progress) to Metric (how we count it).
3. Choose **one primary metric**, plus one or two **guardrails**: things that must not get worse, such as support tickets or error rate.
4. Each metric gets a definition (numerator and denominator), baseline, target, date and data source (e.g. the product analytics tool, the app database).
5. **Baseline unknown** is a valid entry. Never invent one. Add an open question to get it.
6. Prefer behaviour (did they do it) over opinion (did they like it). Don't count outputs such as features shipped.
7. Check that the metric can be measured with the tools in the knowledge base. If it can't, say what is missing.

Method: HEART and Goals-Signals-Metrics, Kerry Rodden, Google (https://www.productplan.com/glossary/heart-framework/).
