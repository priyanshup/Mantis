# Jobs to be done

1. Write **one primary job** and at most five supporting jobs.
2. Write the primary job as a job story: **When** <situation>, **I want to** <motivation>, **so I can** <outcome>. The situation is a trigger in the user's day ("when stock arrives at the warehouse"), not a screen.
3. Supporting jobs in an epic are plain verb phrases ("Download a stock template"), each marked MVP or Post MVP. This matches the team's epic format (reference in `CLAUDE.local.md`).
4. Every job comes from a source (interview, field visit, meeting). Mark it **assumed** if not.
5. Test each job: does it describe progress the user wants without naming our solution? "Upload a CSV" is a solution. "Update all my stock in one go" is a job.
6. Order jobs in the user's real sequence, then check nothing is missing between them (e.g. fixing errors between validating and confirming).

Method: job stories, Intercom and Alan Klement (https://www.intercom.com/blog/accidentally-invented-job-stories/).
