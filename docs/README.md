# docs

How Mantis works. Three groups, by the question each answers.

## rules/ — how Mantis must behave

| File | Read it when |
|---|---|
| `PROJECT_VISION.md` | Always: the purpose and the rules that never change. |
| `WORKFLOW.md` | Ingesting, processing answers or edits from the site, the daily brief. A one-page checklist. |
| `WORKFLOW_RULES.md` | A checklist step points to a rule (confidence, conflicts, assumptions). Open only the section named. |
| `OUTPUTS_GUIDE.md` | Writing anything for a reader: feature pages, epics, stories, answers. |
| `WRITING_STYLE.md` | Checking tone and wording before handing text over. |

## system/ — how Mantis is built

| File | Read it when |
|---|---|
| `SYSTEM_ARCHITECTURE.md` | Changing how the pieces fit: layers, generated files, the site. |
| `ARCHITECTURE_DECISIONS.md` | You need the reason behind a design choice (AD-001 onwards). |
| `MAINTENANCE.md` | Cleaning up: what is generated, what is removed automatically, what is kept. |
| `SKILLS.md` | Setting up a machine, or choosing a skill or tool. |

## project/ — plans and history

| File | Read it when |
|---|---|
| `IMPROVEMENT_BACKLOG.md` | Recording or picking up an idea for improving Mantis itself (shown on the site's backlog page). |
| `PROJECT_PLAN.md` | Checking what was planned for Mantis and in what order. |
| `RENAME_LOG.md` | You meet the old name PKB and need to know what changed. |
